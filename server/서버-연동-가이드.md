# 서버(Apps Script) 연동 마무리 가이드

촬영 페이지(v1.9.1)와 서버 Code.gs v2.3의 전송 규약은 서로 맞습니다. **Code.gs는 고치지 않습니다.** 관리자 화면(`Admin.html`)만 v2.4로 바꿉니다.

## 점검 결과: 촬영 페이지 ↔ 서버

| 항목 | 촬영 페이지 | 서버 Code.gs v2.3 | 결과 |
|---|---|---|---|
| 전송 방식 | form POST + 숨은 iframe | `transport=form`이면 postMessage HTML로 응답 | 일치 |
| 행사 코드 | `BOKJEONG-2026` | `CONFIG.EVENT_CODE` 같음 | 일치 |
| 접수번호 | `H-` + 6자리 (0/O/1/I 제외) | 같은 정규식으로 검사 | 일치 |
| 부스 | B1·B2·B3 | `BOOTHS` 같음 | 일치 |
| 역사 인물 | 항상 `none` | 허용 목록에 `none` 있음 | 일치 (서버 수정 불필요) |
| 이미지 | JPEG, 1.5MB 이하로 자동 압축 | JPEG만, 2MB 이하 | 일치 |
| 재전송 | 같은 접수번호로 재전송 | 같은 번호는 새 파일 없이 성공 처리 | 일치 |
| 추가 필드 | 디자인·버전 등 | 무시함 (오류 아님) | 문제없음 |

## Admin.html v2.4에서 바뀐 점

1. **A4 한 장에 8장 인쇄**: 기존 2×2(4장)는 사진이 1:3 세로형이라 칸마다 양옆이 비었습니다. 4열×2줄로 같은 크기(약 4.75×14.25cm)를 8장 배치합니다. 종이가 절반으로 줍니다.
2. **접수번호 찾기**: 학생이 번호를 말하면 검색 칸에 뒤 몇 글자만 쳐도 찾습니다. Enter를 누르면 찾은 항목이 선택됩니다.
3. **15초마다 자동 새로고침(선택)**: 무엇인가 체크해 둔 동안은 선택이 풀리지 않도록 건너뜁니다.
4. 상태를 바꾸면 선택이 자동으로 풀립니다.

## 적용 순서

1. Apps Script 편집기에서 `Admin.html` 파일 내용을 전부 지우고, 이 폴더의 `Admin.html` 내용을 붙여 넣은 뒤 저장합니다.
2. **배포 → 배포 관리** → **관리자 배포**의 연필(수정) → 버전 **새 버전** → 배포. 주소는 그대로입니다.
3. 업로드 배포는 건드리지 않습니다. (Code.gs가 바뀌지 않았기 때문)

## 리허설 (행사 전 한 번)

1. 부스 크롬북에서 `https://gtmc-history.github.io/history4cut/?booth=B1`을 엽니다.
2. 네 컷을 찍고 스티커를 붙인 뒤 접수 → 완료 화면의 접수번호를 적어 둡니다.
3. 운영대장 시트에 한 줄이 생겼는지, 사진 폴더에 JPG가 생겼는지 확인합니다.
4. 관리자 화면에서 접수번호를 검색 → 선택 → **A4 인쇄**. 인쇄 창에서 **A4 · 배율 100%(실제 크기) · 여백 기본값**으로 인쇄해 자로 4.75×14.25cm인지 확인합니다.
5. **선택 출력 완료** → **선택 배부 완료**로 상태가 바뀌는지 확인합니다.
6. B2·B3 주소로도 한 장씩 동시에 접수해 봅니다.
7. 인터넷을 끊고 접수 → '사진 보관하고 다음 팀' → 인터넷 복구 후 보관 목록에서 재전송해 봅니다.
8. 리허설 사진은 행사 직전에 관리자 화면의 **행사 데이터 일괄 삭제**로 지웁니다. (모든 사진이 지워지니 행사 시작 전에만)

## 행사 후

1. 관리자 화면 **행사 데이터 일괄 삭제** (첫 화면 안내문 "행사가 끝나면 모두 삭제됩니다"를 지키는 단계)
2. 업로드 배포를 **보관(Archive)** 하거나 행사 코드를 바꿔 더 이상 접수되지 않게 합니다. 촬영 페이지가 공개 주소라 누구나 열 수 있기 때문입니다.
